# AutoAccept Electrical

> **Статус: в активной разработке** — реализованы два рабочих шаблона журналов (ОЖР, ЖВК), хранилище Excel-файлов, валидация полей и сохранение в DOCX. Извлечение из PDF/OCR и полный комплект актов — в планах.

Программный комплекс для автоматизации создания приёмо-сдаточной документации в области электромонтажных работ. Целевая аудитория — инженеры ПТО, производители работ и подрядные организации, оформляющие акты, протоколы и журналы по требованиям **СНиП 3.05.06-85** и **ПУЭ-7**.

Подробное описание продукта и планируемых функций — в [Documents/Питч_AAE.md](Documents/Питч_AAE.md).

---

## Задача проекта

Ручное заполнение актов техготовности, журналов прокладки кабелей, паспортов заземлений и смежных форм отнимает значительную часть рабочего времени. AutoAccept Electrical призван:

- собирать данные из Excel, PDF и изображений;
- заполнять отраслевые шаблоны документов;
- формировать итоговый комплект документации для сдачи заказчику.

## Архитектура

Гибридное десктоп-приложение: **WPF (C#)** для интерфейса, **Python** — для парсинга файлов и генерации документов.

```
┌──────────────────────────────────────────────────────────────────┐
│                   Application (WPF, .NET 4.7.2)                  │
│  MainWindow · шаблоны ОЖР/ЖВК · DataGrid · валидация · Storage  │
└────────────────────────────┬─────────────────────────────────────┘
                             │ Process + JSON (stdout / temp-файлы)
┌────────────────────────────▼─────────────────────────────────────┐
│                       Python-модули                              │
│  File_extractors/  — XLSX, PDF, OCR (Tesseract)                  │
│  File_builder/     — сборка итоговых .docx (DOCX_table_builder) │
└────────────────────────────┬─────────────────────────────────────┘
                             │
┌────────────────────────────▼─────────────────────────────────────┐
│  data/  — локальное хранилище Excel и документов объекта         │
└──────────────────────────────────────────────────────────────────┘
```

Типовой сценарий: пользователь кладёт Excel в `data/`, выбирает шаблон и источник данных, настраивает параметры → C# вызывает `XLSX_extractor.py` → строит таблицу предпросмотра → при сохранении сериализует данные в JSON и передаёт в `DOCX_table_builder.py`.

## Текущий функционал

### Реализовано

**Интерфейс и шаблоны**

- **WPF-интерфейс** с деревом шаблонов, поиском по названию и контекстными подсказками
- **Шаблон ОЖР** (`OJR_template`) — раздел 3 общего журнала работ: фильтр по разделу (АК-1, ЭМ-5 и т.д.), обрезка строк сверху/снизу, подстановка должности и ФИО
- **Шаблон ЖВК** (`ZHV_template`) — журнал входного учёта и контроля качества материалов: шапка документа (объект, адрес, организация, даты), значения по умолчанию для поставщика, вида и результата контроля, предпросмотр шапки в реальном времени

**Хранилище данных**

- Каталог **`data/`** для Excel-файлов и документов объекта
- Окно **«Хранилище данных»** — создание папок, добавление и переименование файлов, удаление, открытие в проводнике
- **ComboBox источника данных** — выбор Excel только из хранилища; кнопка перехода к управлению файлами

**Извлечение и генерация**

- **Импорт из Excel** — `XLSX_extractor.py` → JSON → `Json_to_array_convertor` → таблица предпросмотра
- **Сохранение в DOCX** — `DataTable_to_json` + `DOCX_table_builder.py` с оформленной шапкой для ОЖР и ЖВК
- **Извлечение текста из PDF** — `PDF_extractor.py` (PyMuPDF, pdfplumber) — модуль готов, не подключён к основному сценарию UI
- **OCR изображений в PDF** — Tesseract с предобработкой (OpenCV) — в составе `PDF_extractor.py`

**Валидация**

- Проверка обязательных полей перед генерацией (`GenerateDocumentValidator`)
- Проверка наличия запрошенного раздела в Excel (`SectionDocumentValidator`)
- Проверка таблицы и полей перед сохранением (`SaveDocumentValidator`, `ZhvFieldsValidator`)
- Диалоги с перечнем ошибок (`ValidationDialog`)

**Инфраструктура**

- **Мост C# ↔ Python** — `Auxiliary_modules/launch_script/launch_and_data_extraction.cs`
- **Разрешение путей к проекту** — `ResolveProjectPathClass` (корень репозитория относительно `bin/`)
- **Состояние документа** — `FileClass` (сырые данные Excel, таблица предпросмотра, ключ шаблона)

### В разработке / запланировано

- Подключение PDF/OCR к основному рабочему процессу
- Расширение дерева шаблонов (акты, протоколы, журналы прокладки кабелей и др.)
- Экспорт в PDF, электронная подпись, автоматическая сборка полного комплекта документации

## Запуск

**Требования:** Windows, Visual Studio 2019+, .NET Framework 4.7.2, Python 3.x.

1. Открыть `Application/Autoaccept-electrical-app.slnx` в Visual Studio и собрать проект.
2. Создать виртуальное окружение и установить зависимости Python:

```powershell
cd File_extractors
python -m venv .venv
.\.venv\Scripts\pip install -r requirements.txt
```

3. Для OCR: в `File_extractors/TessOCR/` лежит бинарник Tesseract (не ставится через pip); при необходимости обновите пути в `PDF_extractor.py`.
4. Положить Excel-файлы в `data/` (или через «Хранилище данных» в приложении), выбрать шаблон ОЖР или ЖВК, указать источник и нажать «Сгенерировать».

Все пакеты перечислены в [`File_extractors/requirements.txt`](File_extractors/requirements.txt):

| Пакет | Назначение |
|-------|------------|
| `pandas`, `openpyxl` | Чтение Excel (`XLSX_extractor.py`) |

| `pymupdf`, `pdfplumber` | Извлечение текста из PDF (`PDF_extractor.py`) |

Бинарник **Tesseract** поставляется отдельно в `File_extractors/TessOCR/` и в `requirements.txt` не входит.
